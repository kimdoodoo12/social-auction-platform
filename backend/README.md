# 경매 인증과 회귀 검증

## 입찰 금액과 최고가

대기 상태에서는 시작가 이상으로 첫 입찰할 수 있다. `firstBid`는 대기 상태에서 `auctionConfirmed`로 가격 검증·저장을 마친 뒤 시작·종료 시간을 설정하고 진행 상태로 바꾼다. 진행 중에는 기존 최고가보다 최소 1,000원 높아야 한다. 1,000원의 정수 배수 제약을 새로 추가하지는 않는다.

`auctionConfirmed`는 입찰 INSERT가 한 건 성공한 직후 `auctionEntity.setTopPrice(...)`를 호출한다. `placeBid`가 잠근 엔티티의 최고가를 같은 트랜잭션에서 갱신하여 다음 입찰이 최신 가격을 기준으로 검증되게 한다.

수동 확인: 각 상품의 시작가로 첫 입찰이 가능한지, 시작가 미만은 거절되는지, 이후 동일 가격은 거절되고 최고가보다 1,000원 이상 높은 입찰이 가능한지 확인한다.

## 입찰 회원 식별

`UserAuctionController.placeBid`는 `accessToken` 쿠키를 기존 `JWTutil.getMnoFromToken`으로 검증한다. 검증 실패나 쿠키 누락 시 큐에 넣기 전에 `LoginRequiredException`을 던진다. 공통 `AuctionExceptionHandler.handleLoginRequired`가 HTTP 401과 `LOGIN_REQUIRED`, `로그인이 필요합니다.`를 반환한다.

HTTP 요청은 `AuctionBidRequest`의 `auctionId`, `price`만 받는다. 기존 클라이언트가 보낸 `memberId`는 무시한다. 컨트롤러가 검증된 회원 ID로 내부 `AuctionConfirmDto`를 생성하고, 기존 큐 → 서비스 → 입찰 저장·관심 점수 → 커밋 후 SSE 흐름으로 전달한다. 내부 DTO를 HTTP 요청 DTO로 재사용하지 않는다. 인증 방식 변경은 컨트롤러의 인증 경계와 JWT 구현에서 처리하며 서비스와 큐는 쿠키에 의존하지 않는다.

상품 조회는 비로그인 접근을 허용하고, 검증된 회원 ID가 있을 때만 관심 기록을 남기는 기존 동작을 유지한다. 경매 종료의 낙찰자 ID는 로그인 사용자가 아니라 DB 입찰 결과에서 결정한다.

요청 DTO 검증 실패는 공통 `handleValidation`에서 HTTP 400, `BAD_REQUEST`, 고정 메시지로 변환한다. 예상하지 못한 오류는 기존 500 처리를 유지한다. 새 주석은 `// *`로 흐름, `// !`로 신원 검증·데이터 제약을 표시한다.

## 검증

아래 항목을 실제 요청으로 확인한다.

- 정상 쿠키로 회원 ID 없이 입찰하면 성공한다.
- 다른 회원 ID를 본문에 넣어도 큐와 서비스에는 토큰의 회원 ID만 전달된다.
- 쿠키 누락 또는 JWT 검증 결과가 무효인 경우 401이며 큐·서비스를 호출하지 않는다.
- 필수값 누락·0 이하 금액은 400이다.
- 비로그인 상품 조회와 로그인 회원의 관심 기록용 ID 전달을 유지한다.

실환경에서는 두 계정으로 입찰하여 DB의 입찰 회원과 SSE `bidderName`이 각각 로그인 회원과 일치하는지, 만료·변조 토큰으로 입찰이 저장되지 않는지 확인한다. `.env` 파일은 읽거나 수정하지 않는다.
